SECTION 1 — EXECUTIVE SUMMARY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

MedLink Pro is a multi-portal healthcare management system connecting Doctors,
Patients, and Diagnostic Labs/Pharmacies in one unified platform. The system
eliminates paper records, streamlines appointment booking, enables digital
prescriptions and PDF generation, facilitates lab report uploads, and provides
analytics dashboards for practitioners.

Core Portals:
  1. Doctor Portal         — Practice management, scheduling, prescriptions
  2. Patient Portal        — Appointments, records, lab booking, medicines
  3. Lab / Diagnostics     — Report upload, appointment tracking
  4. Admin Panel           — Platform management, analytics, billing

SECTION 2 — USER ROLES & PERMISSIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

ROLE 1 — DOCTOR
  - Register/enroll with profile, speciality, qualifications, clinic info
  - Manage own patients (add, update, view history)
  - Manage appointments (create, modify, cancel)
  - Write prescriptions (medicines, dosage, instructions)
  - Order lab tests, view lab reports
  - Refer patients to other enrolled doctors
  - Generate and print PDFs (prescription slip, reports summary)
  - Calendar management (availability, blocked slots)
  - View analytics dashboard (monthly reports, referral stats, revenue)
  - Search patients by ID, name, phone, appointment ID

ROLE 2 — DOCTOR'S ASSISTANT
  - Sub-role under a Doctor account
  - Block/manage doctor's calendar
  - Add/edit appointment slots
  - View (not modify) patient records
  - Cannot write prescriptions

ROLE 3 — PATIENT
  - Login via phone number (OTP-based)
  - Multiple family members per phone number (profile switcher)
  - View appointment history
  - Book appointments (search by doctor, illness, speciality, location)
  - Book lab tests for a specific appointment
  - Order medicines online
  - Upload personal reports (PDF, images, X-rays)
  - View reports uploaded by labs and doctors
  - Receive digital prescription PDF

ROLE 4 — LAB / DIAGNOSTIC CENTER
  - Register as a lab partner
  - View appointments assigned for lab tests
  - Upload reports directly against Appointment ID
  - Manage test catalog and pricing
  - Notify doctor and patient on report upload

ROLE 5 — PLATFORM ADMIN
  - Approve/reject doctor and lab registrations
  - Manage all users
  - View platform-wide analytics
  - Manage subscription/billing plans
  - Content management (diseases list, medicine catalog)

SECTION 3 — DATA MODELS (Database Schema)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

TABLE: users
  - user_id           (UUID, PK)
  - phone             (VARCHAR, unique)
  - email             (VARCHAR, nullable)
  - full_name         (VARCHAR)
  - role              (ENUM: doctor, patient, lab, assistant, admin)
  - profile_photo     (URL)
  - created_at        (TIMESTAMP)
  - is_verified       (BOOLEAN)
  - is_active         (BOOLEAN)

TABLE: doctors
  - doctor_id         (UUID, PK, FK → users.user_id)
  - doctor_code       (VARCHAR, unique, auto-generated e.g. DOC-00123)
  - registration_no   (VARCHAR)           — Medical council number
  - speciality        (VARCHAR)           — Cardiologist, Neurologist, etc.
  - sub_speciality    (VARCHAR)
  - qualifications    (TEXT)              — MBBS, MD, etc.
  - clinic_name       (VARCHAR)
  - clinic_address    (TEXT)
  - consultation_fee  (DECIMAL)
  - bio               (TEXT)
  - languages         (ARRAY VARCHAR)
  - available_days    (ARRAY VARCHAR)
  - slot_duration_min (INT, default 15)
  - is_approved       (BOOLEAN)

TABLE: doctor_assistants
  - assistant_id      (UUID, PK)
  - doctor_id         (FK → doctors.doctor_id)
  - user_id           (FK → users.user_id)
  - permissions       (JSON)              — e.g. {calendar:true, records:false}

TABLE: patients
  - patient_id        (UUID, PK)
  - patient_code      (VARCHAR, unique, auto-generated e.g. PAT-00456)
  - primary_phone     (VARCHAR)
  - full_name         (VARCHAR)
  - date_of_birth     (DATE)
  - gender            (ENUM: male, female, other)
  - blood_group       (VARCHAR)
  - address           (TEXT)
  - emergency_contact (VARCHAR)
  - allergies         (TEXT)
  - chronic_conditions(TEXT)
  - added_by_doctor   (FK → doctors.doctor_id, nullable)
  - created_at        (TIMESTAMP)

TABLE: patient_family_members
  - member_id         (UUID, PK)
  - primary_phone     (VARCHAR)           — shared with head of family
  - full_name         (VARCHAR)
  - relation          (VARCHAR)
  - date_of_birth     (DATE)
  - gender            (ENUM)
  - patient_id        (FK → patients.patient_id)

TABLE: appointments
  - appointment_id    (UUID, PK)
  - appointment_code  (VARCHAR, unique, auto-generated e.g. APT-20240601-001)
  - doctor_id         (FK → doctors.doctor_id)
  - patient_id        (FK → patients.patient_id)
  - appointment_date  (DATE)
  - appointment_time  (TIME)
  - status            (ENUM: scheduled, in-progress, completed, cancelled, no-show)
  - visit_type        (ENUM: first-visit, follow-up, emergency)
  - chief_complaint   (TEXT)
  - notes             (TEXT)
  - is_telemedicine   (BOOLEAN)
  - created_at        (TIMESTAMP)
  - created_by        (FK → users.user_id)

TABLE: consultations
  - consultation_id   (UUID, PK)
  - appointment_id    (FK → appointments.appointment_id)
  - subjective        (TEXT)             — Patient's reported symptoms
  - objective         (TEXT)             — Doctor's observations
  - assessment        (TEXT)             — Diagnosis
  - plan              (TEXT)             — Treatment plan
  - diagnosis_codes   (ARRAY VARCHAR)    — ICD-10 codes
  - vital_signs       (JSON)             — {bp, pulse, temp, weight, height, spo2}
  - follow_up_date    (DATE)
  - created_at        (TIMESTAMP)

TABLE: prescriptions
  - prescription_id   (UUID, PK)
  - consultation_id   (FK → consultations.consultation_id)
  - appointment_id    (FK → appointments.appointment_id)
  - doctor_id         (FK → doctors.doctor_id)
  - patient_id        (FK → patients.patient_id)
  - issued_at         (TIMESTAMP)
  - valid_until       (DATE)
  - notes             (TEXT)
  - pdf_url           (URL)

TABLE: prescription_medicines
  - item_id           (UUID, PK)
  - prescription_id   (FK → prescriptions.prescription_id)
  - medicine_name     (VARCHAR)
  - dosage            (VARCHAR)          — e.g. 500mg
  - frequency         (VARCHAR)          — e.g. twice daily
  - duration          (VARCHAR)          — e.g. 7 days
  - instructions      (TEXT)             — after meal, with water
  - quantity          (INT)

TABLE: lab_orders
  - lab_order_id      (UUID, PK)
  - appointment_id    (FK → appointments.appointment_id)
  - doctor_id         (FK → doctors.doctor_id)
  - patient_id        (FK → patients.patient_id)
  - lab_id            (FK → labs.lab_id, nullable)
  - tests_ordered     (JSON ARRAY)       — [{test_name, test_code, urgency}]
  - status            (ENUM: ordered, lab-assigned, sample-collected, processing, completed)
  - notes             (TEXT)
  - created_at        (TIMESTAMP)

TABLE: lab_reports
  - report_id         (UUID, PK)
  - lab_order_id      (FK → lab_orders.lab_order_id)
  - appointment_id    (FK → appointments.appointment_id)
  - patient_id        (FK → patients.patient_id)
  - uploaded_by       (FK → users.user_id)
  - report_title      (VARCHAR)
  - report_type       (ENUM: blood-test, urine-test, x-ray, mri, ct-scan, ecg, other)
  - file_url          (URL)
  - file_type         (VARCHAR)          — pdf, jpg, png, dicom
  - notes             (TEXT)
  - uploaded_at       (TIMESTAMP)
  - is_visible_patient(BOOLEAN, default true)

TABLE: referrals
  - referral_id       (UUID, PK)
  - appointment_id    (FK → appointments.appointment_id)
  - referring_doctor  (FK → doctors.doctor_id)
  - referred_to_doctor(FK → doctors.doctor_id)
  - patient_id        (FK → patients.patient_id)
  - reason            (TEXT)
  - urgency           (ENUM: routine, urgent, emergency)
  - notes             (TEXT)
  - status            (ENUM: sent, accepted, rejected, completed)
  - created_at        (TIMESTAMP)

TABLE: labs
  - lab_id            (UUID, PK)
  - lab_code          (VARCHAR, unique)
  - name              (VARCHAR)
  - address           (TEXT)
  - phone             (VARCHAR)
  - email             (VARCHAR)
  - accreditation     (VARCHAR)
  - tests_catalog     (JSON)
  - operating_hours   (JSON)
  - is_approved       (BOOLEAN)
  - user_id           (FK → users.user_id)

TABLE: doctor_calendar
  - slot_id           (UUID, PK)
  - doctor_id         (FK → doctors.doctor_id)
  - slot_date         (DATE)
  - slot_time         (TIME)
  - slot_duration_min (INT)
  - status            (ENUM: available, booked, blocked, break)
  - blocked_by        (FK → users.user_id, nullable)
  - block_reason      (VARCHAR)
  - appointment_id    (FK → appointments.appointment_id, nullable)

TABLE: medicines_catalog
  - medicine_id       (UUID, PK)
  - name              (VARCHAR)
  - generic_name      (VARCHAR)
  - category          (VARCHAR)
  - manufacturer      (VARCHAR)
  - price             (DECIMAL)
  - unit              (VARCHAR)           — tablet, syrup, injection
  - requires_prescription (BOOLEAN)
  - stock_qty         (INT)
  - image_url         (URL)

TABLE: medicine_orders
  - order_id          (UUID, PK)
  - patient_id        (FK → patients.patient_id)
  - prescription_id   (FK → prescriptions.prescription_id, nullable)
  - items             (JSON ARRAY)        — [{medicine_id, qty, price}]
  - total_amount      (DECIMAL)
  - status            (ENUM: placed, confirmed, dispatched, delivered, cancelled)
  - delivery_address  (TEXT)
  - created_at        (TIMESTAMP)

TABLE: notifications
  - notification_id   (UUID, PK)
  - user_id           (FK → users.user_id)
  - type              (VARCHAR)           — appointment, report, referral, order
  - title             (VARCHAR)
  - message           (TEXT)
  - is_read           (BOOLEAN)
  - created_at        (TIMESTAMP)
  - action_url        (VARCHAR)

TABLE: patient_documents
  - doc_id            (UUID, PK)
  - patient_id        (FK → patients.patient_id)
  - title             (VARCHAR)
  - doc_type          (ENUM: xray, mri, blood-report, prescription, other)
  - file_url          (URL)
  - uploaded_by_role  (ENUM: patient, doctor, lab)
  - appointment_id    (FK → appointments.appointment_id, nullable)
  - uploaded_at       (TIMESTAMP)

AUTH
  POST   /auth/otp/request             — Request OTP (phone)
  POST   /auth/otp/verify              — Verify OTP → JWT token
  POST   /auth/register/doctor         — Doctor self-registration
  POST   /auth/register/lab            — Lab self-registration
  POST   /auth/logout                  — Invalidate token
  GET    /auth/me                      — Current user info

SECTION 5 — DOCTOR PORTAL: FEATURE DETAIL
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

5.1 REGISTRATION & PROFILE
  - Registration form: name, phone, email, speciality, sub-speciality
  - Upload: photo, degree certificates, medical council registration
  - Clinic details: name, address, GPS coordinates, operating hours
  - Admin reviews and approves profile before going live
  - Each doctor gets a unique Doctor ID (DOC-XXXXX)
  - Profile shows: experience, languages spoken, availability, fees

5.2 DASHBOARD (Home)
  - Today's appointment count
  - Upcoming appointments list (next 4 hours)
  - Pending lab reports to review
  - Pending referrals (incoming)
  - Recent patient activity
  - Quick actions: Add Patient, New Appointment, View Calendar

5.3 PATIENT MANAGEMENT
  - Add patient manually: name, phone, DOB, gender, blood group, address, allergies
  - Each patient gets unique Patient ID (PAT-XXXXX)
  - Patient search: by ID, name, phone number, appointment code
  - Patient timeline view: all appointments, prescriptions, reports in chronological order
  - Edit patient demographics
  - Flag patients (VIP, high-risk, chronic)
  - Patient notes (private doctor notes)

5.4 APPOINTMENT FLOW
  Step 1: Select patient (search or add new)
  Step 2: Pick date/time from available calendar
  Step 3: Set visit type (first visit / follow-up / emergency)
  Step 4: Add chief complaint
  Step 5: Save → Appointment ID generated (APT-YYYYMMDD-XXX)

  During consultation:
  - Record vital signs (BP, pulse, temperature, SpO2, weight, height)
  - Write SOAP notes (Subjective / Objective / Assessment / Plan)
  - Add diagnosis (free text or ICD-10 search)
  - Add medicines (search catalog or free type)
    - Medicine name, dosage, frequency, duration, instructions
  - Order lab tests (select from standard test list)
  - Add follow-up date
  - Refer to another doctor (select from enrolled doctors by speciality)

5.5 PRESCRIPTION PDF GENERATION
  Header: Clinic logo, doctor name, qualifications, registration number, clinic address
  Patient info: Name, Age, Gender, Patient ID, Date
  Vital signs block
  Diagnosis section
  Medicine table: Name | Dosage | Frequency | Duration | Instructions
  Lab tests ordered
  Follow-up date
  Doctor signature block
  Powered by MedLink Pro footer
  Options: Preview → Print / Download PDF / Share via WhatsApp

5.6 REPORTS TAB (Doctor)
  - Lab Reports: all reports for all patients, filterable by date/patient/type
  - Upload Documents: doctor can upload documents against patient + appointment
  - Analytics sub-tab:
    * Appointments per day/week/month (bar chart)
    * Top diagnoses (pie chart)
    * New vs returning patients (line chart)
    * Referrals sent vs received
    * Revenue / consultation fees collected
    * Patient demographics (age, gender breakdown)
  - Monthly summary downloadable as PDF

5.7 REFERRALS
  - When creating a referral: select speciality → filtered list of enrolled doctors
  - Add reason, urgency, clinical notes
  - Referred doctor receives notification
  - Referring doctor can track referral status
  - Patient is notified of referral

5.8 CALENDAR
  - Month / Week / Day view
  - Color coding: Available (green), Booked (blue), Blocked (red), Break (yellow)
  - Doctor can set recurring availability (e.g. Mon-Fri 10am-2pm)
  - Doctor or assistant can block specific time slots with reason
  - Drag to reschedule appointments (with patient notification)
  - Telemedicine slots marked separately
  - Export calendar to Google Calendar / iCal

5.9 SEARCH FUNCTIONALITY (Doctor)
  Search bar accepts:
  - Patient name (partial match)
  - Patient ID (PAT-XXXXX)
  - Phone number
  - Appointment ID (APT-YYYYMMDD-XXX)
  - Diagnosis keyword
  Results show: patient card with quick-link to profile and latest appointment

SECTION 6 — PATIENT PORTAL: FEATURE DETAIL
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

6.1 LOGIN FLOW
  - Enter phone number → receive OTP via SMS
  - Enter OTP → logged in
  - If multiple patients linked to that phone:
    * Show family member list with photos/names
    * User selects which patient profile to use
    * Can switch profiles anytime from top bar

6.2 PATIENT DASHBOARD
  - Upcoming appointment card (date, time, doctor, clinic)
  - Pending lab test status
  - Recent prescriptions (last 3)
  - Notifications bell
  - Quick links: Book Appointment, My Reports, Order Medicine

6.3 FIND A DOCTOR & BOOK APPOINTMENT
  Search by:
  - Doctor name
  - Speciality (Cardiologist, Dermatologist, etc.)
  - Illness / symptoms (mapped to speciality)
  - Location / area
  - Language
  - Availability (today, tomorrow, this week)
  - Consultation fee range

  Doctor card shows:
  - Photo, name, speciality, qualifications
  - Clinic name and address
  - Average rating and reviews
  - Next available slot
  - Consultation fee
  - "Book Now" button

  Booking flow:
  Step 1: Select available slot from calendar
  Step 2: Select patient (self or family member)
  Step 3: Enter chief complaint / reason for visit
  Step 4: Confirm and pay (optional, if payment enabled)

SECTION 10 — TECHNOLOGY STACK RECOMMENDATIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

FRONTEND — WEB
  Framework     : Next.js 14+ (React, TypeScript)
  UI Library    : Tailwind CSS + Shadcn/UI
  State Mgmt    : Zustand or Redux Toolkit
  Forms         : React Hook Form + Zod validation
  Charts        : Recharts or Chart.js
  PDF Generation: React-PDF / jsPDF (client-side)
  Calendar      : FullCalendar.js
  File Upload   : react-dropzone
  Video Call    : Twilio Video SDK / Daily.co

FRONTEND — MOBILE
  Framework     : React Native (Expo) OR Flutter
  Navigation    : React Navigation v6
  Push Notif.   : Expo Notifications / Firebase Cloud Messaging
  Storage       : MMKV / AsyncStorage
  Camera/Files  : Expo Camera, Expo Document Picker

BACKEND
  Runtime       : Node.js with Express OR NestJS (TypeScript)
  Authentication: JWT + Refresh tokens, OTP via SMS gateway
  ORM           : Prisma (PostgreSQL)
  File Storage  : AWS S3 / Cloudflare R2
  PDF Engine    : Puppeteer (server-side PDF) OR PDFKit
  Queue/Jobs    : Bull (Redis) for notifications, PDF generation
  Search        : PostgreSQL full-text search OR Elasticsearch
  SMS Gateway   : Twilio / MSG91 / Fast2SMS (India)
  Push Notif.   : Firebase Cloud Messaging (FCM)
  Email         : SendGrid / AWS SES
  Video         : Twilio Programmable Video

DATABASE
  Primary DB    : PostgreSQL 15+
  Cache         : Redis (sessions, OTP, calendar slots)
  Search Index  : Elasticsearch (optional, for large deployments)
  File Storage  : AWS S3 with pre-signed URLs

INFRASTRUCTURE
  Hosting       : AWS / DigitalOcean / Vercel (web)
  CI/CD         : GitHub Actions
  Monitoring    : Sentry (errors), Datadog (performance)
  SSL           : Let's Encrypt / CloudFlare
  CDN           : CloudFront / Cloudflare

SECURITY
  - HTTPS everywhere
  - JWT with short expiry + refresh token rotation
  - OTP rate limiting (max 3 attempts / 10 min)
  - Role-based access control (RBAC) on every endpoint
  - File upload: type validation, size limits, virus scan (ClamAV)
  - HIPAA/data privacy compliant storage (encrypted at rest)
  - Audit log for all data access and modifications
  - OWASP top-10 mitigations

SECTION 14 — NOTIFICATIONS STRATEGY

NOTIFICATION TRIGGERS:
  Appointment booked               → Doctor + Patient (SMS + Push)
  Appointment reminder (24hr)      → Patient (SMS + Push)
  Appointment reminder (1hr)       → Patient (Push)
  Appointment status change        → Patient (SMS + Push)
  Prescription ready               → Patient (Push + WhatsApp link)
  Lab report uploaded              → Doctor + Patient (Push + SMS)
  Lab order assigned               → Lab (Push)
  Referral received                → Target doctor (Push)
  Referral accepted                → Referring doctor + Patient (Push)
  Medicine order shipped           → Patient (SMS + Push)
  Doctor approved by admin         → Doctor (SMS + Email)
  Follow-up due                    → Patient (Push, 1 day before)
  Queue token update               → Patient (Push: "2 patients ahead")

  Accent Color    : #F59E0B (Amber — alerts, action)
  Danger Color    : #EF4444 (Red — errors, cancel)

  - Large touch targets on mobile (min 44x44px)

  - Dark mode support

SECTION 16 — SECURITY & COMPLIANCE CHECKLIST
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  [ ] All API endpoints protected with JWT middleware
  [ ] Role checks on every sensitive endpoint
  [ ] OTP expiry: 5 minutes, max 3 attempts, 10-min lockout
  [ ] Passwords (if any) bcrypt hashed, salt 12
  [ ] All file uploads: type whitelist, 50MB limit, virus scan
  [ ] S3 files accessed via pre-signed URLs (no public URLs)
  [ ] Audit log table for: login, record access, prescription create, report upload
  [ ] Patient data: doctor can only access their own patients (enforced in DB queries)
  [ ] Lab can only access orders and reports of patients assigned to them
  [ ] HTTPS enforced (HSTS headers)
  [ ] CORS configured for known origins only
  [ ] Rate limiting: 100 req/min per IP on public routes
  [ ] SQL injection: parameterised queries via Prisma
  [ ] XSS: output encoding in frontend
  [ ] CSRF: SameSite cookies
  [ ] Sensitive fields encrypted at rest: phone numbers, medical notes
  [ ] Data retention policy: configurable per deployment
  [ ] GDPR/IT Act compliance: user data export and delete on request
